## 🐛 О проблеме

В **сентябре 2026 года** Microsoft выпустила накопительные обновления безопасности, которые сломали работу службы удалённых рабочих столов (RDS/RDP) на широком спектре ОС:

- **Симптомы**: RDP-подключения зависают на экранах «Инициализация удаленного подключения», «Защита удаленного подключения» или «Подождите, идет настройка удаленного рабочего стола».
- **Диагностика**: в системном журнале — события **ID 7011** (тайм-аут 30000 мс) для служб `NlaSvc`, `iphlpsvc`, `UmRdpService`.
- **Сопутствующие сбои**: вместе с RDP перестают отвечать `mmc.exe`, `Проводник`, «Центр обновления Windows».
- **Причина**: взаимоблокировка (deadlock) служб RDS после установки багованных LCU.
- **Решение**: экстренные (OOB) патчи Microsoft, распространяемые **только через Microsoft Update Catalog**.

Полная матрица «проблемное обновление → исправление»:

| ОС | Проблемное обновление | Исправление |
|---|---|---|
| Windows Server 2012 | KB5123065 | KB5129244 |
| Windows Server 2012 R2 | KB5123066 | KB5129243 |
| Windows Server 2016 | KB5123099 | KB5129239 |
| Windows Server 2019 | KB5122876 | KB5129238 |
| Windows Server 2022 | KB5122882 | KB5129237 |
| Windows Server 2025 | KB5122871 | KB5129235 |
| Windows 10 (1507–22H2, LTSC) | см. карту скрипта | см. карту скрипта |
| Windows 11 (21H2–26H1) | см. карту скрипта | см. карту скрипта |

## 🎯 Что делает инструмент

`Check-RdpPatch` автоматически:

1. **Определяет версию ОС** по `BuildNumber` через `Win32_OperatingSystem`.
2. **Различает серверные и клиентские** редакции (по подстроке `Server` в Caption).
3. **Проверяет наличие** проблемного обновления через `Get-HotFix`.
4. **Проверяет наличие** исправляющего патча.
5. **Выводит вердикт**:
   - ✅ Система не затронута багом.
   - ✅ Система защищена.
   - ❌ Требуется установка — со **ссылкой на Microsoft Update Catalog**.
6. **Предоставляет GUI** (для ручного запуска): кнопки **Copy link** и **Open in browser**.

## 🚀 Быстрый старт

### Требования

- PowerShell 5.1 или выше (встроен в Windows 10/11 и Server 2016+).
- Права обычного пользователя для консольной версии.
- Права администратора **не требуются** — скрипт только читает `Get-HotFix`.

### Разрешение на запуск скриптов

Windows по умолчанию блокирует выполнение `.ps1`. Разрешите их для текущего пользователя:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

### Запуск консольной версии

```powershell
cd D:\Repo\Omnissiah_Toolbox\scripts
.\Check-RdpPatch.ps1
```

С автоматическим открытием ссылки в браузере (если требуется патч):

```powershell
.\Check-RdpPatch.ps1 -OpenLink
```

### Запуск GUI-версии

```powershell
.\Check-RdpPatch-GUI.ps1
```

Либо двойным кликом по `Check-RdpPatch.exe` (после сборки).

## 🔨 Сборка EXE

### Установка модуля PS2EXE (один раз)

```powershell
Install-Module -Name ps2exe -Scope CurrentUser -Force
```

Если PSGallery не доверенный:

```powershell
Set-PSRepository -Name PSGallery -InstallationPolicy Trusted
```

### Компиляция

```powershell
Invoke-PS2EXE `
    -InputFile   "D:\Repo\Omnissiah_Toolbox\scripts\Check-RdpPatch-GUI.ps1" `
    -OutputFile  "D:\Repo\Omnissiah_Toolbox\scripts\Check-RdpPatch.exe" `
    -NoConsole `
    -STA `
    -Title       "RDP Patch Check" `
    -Description "Checks for the September 2026 RDP bug and its fix" `
    -Company     "Omnissiah_Toolbox" `
    -Product     "RDP Patch Check" `
    -Version     "1.0.0.0" `
    -Copyright   "2026"
```

Ключевые параметры:

| Параметр | Назначение |
|---|---|
| `-NoConsole` | Скрывает окно PowerShell — остаётся только GUI |
| `-STA` | **Обязательно** для WinForms (иначе окно не появится) |
| `-Title`, `-Version`, `-Company` | Метаданные EXE в свойствах файла |
| `-IconFile "path\to\icon.ico"` | (опционально) своя иконка |

Результат — самодостаточный `Check-RdpPatch.exe` размером ~100–200 КБ.

### GUI

Окно содержит:

- **Поле вывода** — результаты проверки с цветовой подсветкой (зелёный / красный).
- **Download link** — URL каталога Microsoft.
- **Copy link** — копирует URL в буфер обмена.
- **Open in browser** — открывает ссылку в браузере по умолчанию.

## 🎯 Три возможных вердикта

| Ситуация | Вердикт | Действие |
|---|---|---|
| Проблемное обновление НЕ установлено | ✅ Система не затронута | Ничего не делать. Следить за обновлениями. |
| Проблемное установлено + исправление установлено | ✅ Система защищена | Ничего не делать. |
| Проблемное установлено + исправления нет | ❌ Требуется установка | Скачать патч по ссылке, установить, перезагрузить. |

## 🛠️ Установка патча

1. Откройте ссылку из скрипта в браузере (или через кнопку **Open in browser**).
2. Найдите пакет для **x64** и нажмите **Download**.
3. **Скопируйте актуальный URL** на `.msu` из появившегося окна — динамические ссылки Microsoft быстро устаревают, старые возвращают 404.
4. Скачайте файл и установите:

   ```powershell
   Start-Process -FilePath "wusa.exe" `
       -ArgumentList "C:\Temp\KBxxxxxxx.msu /quiet /norestart" -Wait
   ```

5. Проверьте установку:

   ```powershell
   Get-HotFix -Id KBxxxxxxx
   ```

6. **Перезагрузите систему**:

   ```powershell
   Restart-Computer -Force
   ```

> Патч вступает в силу только после перезагрузки.

## ⚠️ Известные нюансы

### Кириллица в консоли отображается кракозябрами
Проблема кодировок: файл в UTF-8, консоль в CP866. В скрипте вывод намеренно оставлен на английском, чтобы избежать искажений. Если нужен русский — сохраните файл в UTF-8 с BOM и запускайте PowerShell 7+.

### SmartScreen блокирует EXE
Неподписанный бинарник вызовет предупреждение «Windows защитила ваш компьютер». Нажмите **«Подробнее» → «Выполнить в любом случае»**. Чтобы избежать этого, нужен код-сертификат.

### Антивирус помечает EXE
Некоторые антивирусы (включая Defender) помечают EXE, собранные через PS2EXE, как «подозрительные» — внутри упакован PowerShell-скрипт. В корпоративной среде добавьте файл в исключения или подпишите сертификатом.

### Dynamic URLs из каталога Microsoft
Ссылки на `.msu` в каталоге генерируются динамически и часто меняются. Не храните их в закладках — всегда получайте свежую через кнопку Download.

### Права
Скрипт **не требует** прав администратора: он только читает информацию через `Get-HotFix` и `Get-CimInstance`. Если `Get-HotFix` возвращает пусто, попробуйте запустить PowerShell от имени администратора.
