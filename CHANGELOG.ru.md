## [1.0.4] — 2026-10-01

### Исправлено
- **Удалён метод детекции `Get-WindowsPackage`** (ранее — Method 5).
  Он возвращал `Installed = $true` для любого KB при наличии хотя бы
  одного пакета `RollupFix` в системе, что давало ложные срабатывания —
  инструмент сообщал о наличии проблемного обновления, когда его не было.
  Теперь детекция опирается только на четыре источника:
  Registry UBR → Get-HotFix → WUA History → DISM.
- **Исправлено значение UBR для Server 2016** по результатам проверки на
  реальном сервере: `9514` → `9339`. Прежнее значение было рассчитано
  теоретически и не совпадало с фактической build revision после установки
  KB5129239 на Windows Server 2016.
- **Отключены клиентские UBR** для платформ без проверенных значений.
  Поля `ProblemUbr` / `FixUbr` теперь выставлены в `0` для таких записей,
  что отключает UBR-детекцию и передаёт решение остальным источникам.
  Это устраняет ложные вердикты «не установлено» / «установлено» на
  системах, где ожидаемый UBR был предположением.

### Изменено
- Детекция теперь использует **четыре источника** вместо пяти. Удаление
  Method 5 (`Get-WindowsPackage`) устраняет класс ложных срабатываний,
  сохраняя покрытие связанных пакетов SSU+LCU через Registry UBR.
- Консольный вывод теперь показывает шаги установки **только при
  отсутствии исправления**. В сценарии «система защищена» печатается
  только ссылка на скачивание — ранее инструмент показывал инструкцию
  по установке, даже когда ничего устанавливать не требовалось.
- Шапки скриптов обновлены: `four sources` вместо `five sources`.

### Проверено
- **Windows Server 2016** (build 14393, UBR 9339) — вердикт корректный.
- **Windows Server 2019** (build 17763, UBR 9247) — вердикт корректный.
- **Windows Server 2022** (build 20348, UBR 5631) — вердикт корректный.
- **Windows 10 22H2** (build 19045, UBR 6456) — вердикт корректный.

## [1.0.3] — 2026-10-01

### Исправлено
- Детекция KB теперь использует **Registry UBR** как основной источник. Связанные
  пакеты SSU+LCU невидимы для `Get-HotFix`, WUA COM history и DISM по номеру KB,
  что давало ложный вердикт «не установлено» на Windows Server 2022 (UBR 5622/5631)
  и других сборках.
- Детекция теперь сообщает источник (`via Registry UBR`, `via Get-HotFix`,
  `via WUA History`, `via DISM` или `via Get-WindowsPackage`).

### Добавлено
- Поля `ProblemUbr` и `FixUbr` в обеих картах патчей — числовые build revisions
  для точного сравнения.
- Значение UBR теперь выводится в шапке консольного и GUI-вывода.

### Проверено
- Windows Server 2022 (build 20348, UBR 5631) — вердикт корректный.
- Windows Server 2019 (build 17763) — вердикт корректный.

## [1.0.1] — 2026-09-30

### Добавлено
- Метаданные автора и лицензии в шапках скриптов:
  - `Author: fixsys-spb`
  - `GitHub: https://github.com/fixsys-spb/Operpatch`
  - `Version: 1.0.1`
  - `License: Internal use`
- Строка авторства в окне GUI: `(c) 2026 fixsys-spb | github.com/fixsys-spb/Operpatch`.
- Строка копирайта в конце вывода консольного скрипта.
- Ссылка на скачивание теперь показывается во всех трёх сценариях вердикта, а не только когда требуется установка. Это позволяет скачать `.msu` заранее, если проблемное обновление ещё не пришло.

### Изменено
- RichTextBox в GUI теперь раскрашивает вывод построчно, а не единым цветом. Строки `[OK]` — зелёные, `[!]` — красные, пояснения — серые. Раньше весь вывод был одного цвета, что скрывало важные предупреждения.
- Консоль: `Write-Err` (красный) заменён на `Write-Warn` (жёлтый) в сценарии «система защищена» — это не ошибка, только предупреждение о наличии проблемного обновления.
- Высота окна GUI увеличена с 580 до 600 px под новую строку авторства.
- Все элементы интерфейса в GUI сдвинуты на 10 px вниз соответственно.

### Исправлено
- **GUI: кнопка Re-check не работала.** `$MyInvocation.MyCommand.Path` возвращает пустое значение внутри блока `Add_Click`. Заменено на `$PSCommandPath` для `.ps1` и `[System.Reflection.Assembly]::GetEntryAssembly().Location` для скомпилированного EXE.
- Удалены мёртвые переменные `$needsAction` и `$fixKb` — устанавливались, но нигде не читались.
- Английский README приведён к структуре русского (раздел про сборку удалён из обоих).

### Удалено
- Раздел «Сборка EXE» из `README.md` и `README.ru.md` (сохранён в `build-exe.ps1` и его встроенной справке).

## [1.0.0] — 2026-09-29

### Добавлено

**Консольный скрипт `Check-RdpPatch.ps1`:**
- Определение ОС по `BuildNumber` через `Win32_OperatingSystem`.
- Разделение карт патчей на серверные (`$ServerPatchMap`) и клиентские (`$ClientPatchMap`).
- Проверка наличия проблемного обновления и исправления через `Get-HotFix`.
- Вердикт по трём сценариям:
  - система не затронута багом;
  - система защищена;
  - требуется установка патча.
- Автогенерация ссылки на Microsoft Update Catalog.
- Ключ `-OpenLink` для открытия ссылки в браузере.

**GUI-версия `Check-RdpPatch-GUI.ps1` (WinForms):**
- Окно 720×580 с заголовком и подзаголовком.
- Цветовая подсветка вердикта (зелёный / красный).
- Поле **Download link** с URL каталога Microsoft.
- Кнопка **Copy link** — копирование URL в буфер обмена.
- Кнопка **Open in browser** — открытие ссылки в браузере.
- Кнопка **Re-check** — повторная проверка.
- Кнопка **Close** — закрытие окна.
- Кнопки ссылки неактивны, если патч не требуется.

**Документация:**
- `README.md` — описание проблемы, поддерживаемые ОС, инструкции.
- `Check-RdpPatch-screenshot.png` — скриншот GUI.

**Клиентские:**

- Windows 11: 21H2, 22H2, 23H2, 24H2, 25H2, 26H1.

## Правила ведения

1. Новые изменения — в секцию `[Unreleased]`.
2. При релизе — новая версия по SemVer:
   - `MAJOR` — несовместимые изменения.
   - `MINOR` — новая обратно совместимая функциональность.
   - `PATCH` — обратно совместимые исправления.
3. Категории: **Добавлено**, **Изменено**, **Устарело**, **Удалено**, **Исправлено**, **Безопасность**.
4. Дата релиза — `YYYY-MM-DD`.
