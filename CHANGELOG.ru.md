## [1.1.0] — 2026-10-01

### Добавлено
- Трёхуровневая классификация сборок:
  - **Supported** — сентябрьская RDP-матрица. Выполняется KB-проверка.
  - **Legacy** — сняты с обслуживания до сентября 2026. Явное сообщение
    «out of servicing», без KB-проверки.
  - **Unknown** — сборка вне наших карт. «No patch data available»,
    без KB-проверки.
- Карта `$LegacyBuilds` для снятых с обслуживания ветвей: Windows 10
  1507, 1511, 1703, 1709, 1803, 1903, 1909, 2004, 20H2, 21H1; Windows 11
  21H2, 22H2.
- Определение ОС через `ProductType` из `Win32_OperatingSystem` —
  корректно работает на локализованных системах (Server vs. Client,
  ProductType 2/3).

### Изменено
- Клиентская карта сокращена до активно обслуживаемых сборок. Удалены:
  Windows 10 1507, 1511, 1703, 1709, 1803, 1903, 1909, 2004, 20H2, 21H1;
  Windows 11 21H2, 22H2. Эти ветки не получают сентябрьские LCU 2026.
- Зафиксирована политика UBR: `ProblemUbr` / `FixUbr` заполняются
  только если Microsoft в карточке Update Catalog явно указывает
  OS Build. Отсутствие данных — `0`, никогда не догадка.
- `Test-KbInstalled` в консольном скрипте выровнен с GUI: валидация
  формата KB, `[regex]::Escape`, фильтр `Package_for_KBxxx`,
  ограничение WUA history в 1000 записей.
- Чтение UBR из реестра теперь проверяет тип возвращаемого значения.

### Исправлено
- Скорректированы UBR:
  - Server 2025: `0/0` → `33438/33451` (KB5122871 / KB5129235).
  - Windows 10 21H2 / 22H2: `0/0` → `7725/7727`
    (KB5122878 / KB5129236).
  - Windows 11 23H2: FixUbr `0` → `7584` (KB5129242).
  - Windows 11 24H2 / 25H2: `0/0` → `9445/9457`
    (KB5124008 / KB5129195).
- Исправлен номер сборки Windows 11 26H1 в клиентской карте:
  `27695` → `28000`. Прежнее значение — insider preview build, оно
  никогда не совпало бы с розничной системой.
- Заполнены UBR для Windows 11 26H1: `2954/2956`
  (KB5124012 / KB5129194).
- Откат UBR для Windows Server 2016 и Windows 10 1607 LTSB 2016
  обратно в `0`. Проверка на живом сервере показала UBR `9339`
  после установки KB5129239, тогда как Microsoft в каталоге указывает
  `9514`. Расхождение говорит о том, что UBR на этой ветке ведёт себя
  иначе, чем на Server 2019/2022/2025. Детекция передаётся
  `Get-HotFix` / WUA history / DISM — они проверены на Server 2016.
- Исправлено экранирование в inline-примере установки
  (backslash → backtick). Прежняя версия выводила `\$url` вместо `$url`.
- Открытие браузера в GUI обёрнуто в try/catch — сообщает об ошибке,
  если `Start-Process` не сработал.

### Проверено на живых системах
- Windows Server 2016 (build 14393, UBR 9339) — вердикт корректный
  через `Get-HotFix`.
- Windows Server 2019 (build 17763, UBR 9247) — вердикт корректный.
- Windows Server 2022 (build 20348, UBR 5631) — вердикт корректный.
- Windows 10 22H2 (build 19045, UBR 6456) — вердикт корректный.
- Протестировано во всех трёх формах: `.ps1`, GUI, EXE.

## [1.0.4] — 2026-10-01

### Исправлено
- **Удалён метод детекции `Get-WindowsPackage`** (ранее — Method 5).
  Он возвращал `Installed = $true` для любого KB при наличии хотя бы
  одного пакета `RollupFix` в системе, что давало ложные срабатывания.
  Теперь детекция опирается только на четыре источника:
  Registry UBR → Get-HotFix → WUA History → DISM.
- **Скорректировано значение UBR для Server 2016** по результатам
  проверки на живом сервере: `9514` → `9339`. (В v1.1.0 откачено
  до `0` — см. выше.)
- **Отключены клиентские UBR** для платформ без проверенных значений.
  Поля `ProblemUbr` / `FixUbr` выставлены в `0` для таких записей,
  что отключает UBR-детекцию и передаёт решение остальным источникам.

### Изменено
- Детекция теперь использует **четыре источника** вместо пяти.
  Удаление Method 5 устраняет класс ложных срабатываний, сохраняя
  покрытие связанных пакетов SSU+LCU через Registry UBR.
- Консольный вывод теперь показывает шаги установки **только при
  отсутствии исправления**. В сценарии «система защищена» печатается
  только ссылка на скачивание.
- Шапки скриптов обновлены: `four sources` вместо `five sources`.

### Проверено
- **Windows Server 2016** (build 14393, UBR 9339) — вердикт корректный.
- **Windows Server 2019** (build 17763, UBR 9247) — вердикт корректный.
- **Windows Server 2022** (build 20348, UBR 5631) — вердикт корректный.
- **Windows 10 22H2** (build 19045, UBR 6456) — вердикт корректный.

## [1.0.3] — 2026-10-01

### Исправлено
- Детекция KB теперь использует **Registry UBR** как основной источник.
  Связанные пакеты SSU+LCU невидимы для `Get-HotFix`, WUA COM history
  и DISM по номеру KB, что давало ложный вердикт «не установлено»
  на Windows Server 2022 (UBR 5622/5631) и других сборках.
- Детекция теперь сообщает источник (`via Registry UBR`,
  `via Get-HotFix`, `via WUA History`, `via DISM` или
  `via Get-WindowsPackage`).

### Добавлено
- Поля `ProblemUbr` и `FixUbr` в обеих картах патчей — числовые
  build revisions для точного сравнения.
- Значение UBR теперь выводится в шапке консольного и GUI-вывода.

### Проверено
- Windows Server 2022 (build 20348, UBR 5631) — вердикт корректный.
- Windows Server 2019 (build 17763) — вердикт корректный.

## [1.0.2] — 2026-09-30

### Добавлено
- README: скриншот «система защищена» (`Check-RdpPatch-screenshot4.png`).

### Исправлено
- Детекция KB теперь использует три независимых источника:
  `Get-HotFix`, WUA COM history и DISM. Ранее связанные пакеты SSU+LCU
  были невидимы для `Get-HotFix`, что давало ложный вердикт
  «не установлено» на Windows Server 2022 и других сборках.
- Вердикт теперь сообщает источник, через который был найден KB.

## [1.0.0] — 2026-09-29

### Добавлено

**Консольный скрипт `Check-RdpPatch.ps1`:**
- Определение ОС по `BuildNumber` через `Win32_OperatingSystem`.
- Разделение карт патчей на серверные (`$ServerPatchMap`) и
  клиентские (`$ClientPatchMap`).
- Проверка наличия проблемного обновления и исправления через
  `Get-HotFix`.
- Вердикт по трём сценариям:
  - система не затронута багом;
  - система защищена;
  - требуется установка патча.
- Автогенерация ссылки на Microsoft Update Catalog.
- Ключ `-OpenLink` для открытия ссылки в браузере.

**GUI-версия `Check-RdpPatch-GUI.ps1` (WinForms):**
- Окно 720×580 с заголовком и подзаголовком.
- Цветовая подсветка вердикта (зелёный / красный).
- Поле **Download link** с URL каталога Microsoft.
- Кнопка **Copy link** — копирование URL в буфер обмена.
- Кнопка **Open in browser** — открытие ссылки в браузере.
- Кнопка **Re-check** — повторная проверка.
- Кнопка **Close** — закрытие окна.
- Кнопки ссылки неактивны, если патч не требуется.

**Документация:**
- `README.md` — описание проблемы, поддерживаемые ОС, инструкции.
- `Check-RdpPatch-screenshot.png` — скриншот GUI.

### Матрица патчей

| ОС | Проблемное обновление | Исправление |
|---|---|---|
| Server 2012 | KB5123065 | KB5129244 |
| Server 2012 R2 | KB5123066 | KB5129243 |
| Server 2016 | KB5123099 | KB5129239 |
| Server 2019 | KB5122876 | KB5129238 |
| Server 2022 | KB5122882 | KB5129237 |
| Server 2025 | KB5122871 | KB5129235 |

### Известные ограничения
- Server 2012 / 2012 R2 не покрыты в GUI.
- Ссылки на `.msu` в каталоге Microsoft динамические.
- EXE от PS2EXE может блокироваться SmartScreen.

## Правила ведения

1. Новые изменения — в секцию `[Unreleased]`.
2. При релизе — новая версия по SemVer:
   - `MAJOR` — несовместимые изменения.
   - `MINOR` — новая обратно совместимая функциональность.
   - `PATCH` — обратно совместимые исправления.
3. Категории: **Добавлено**, **Изменено**, **Устарело**, **Удалено**,
   **Исправлено**, **Безопасность**.
4. Дата релиза — `YYYY-MM-DD`.
