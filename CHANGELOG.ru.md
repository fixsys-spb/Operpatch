## [1.2.0][] — 2026-10-16

### Добавлено
- Единая нумерация релизов для консольного скрипта, GUI-скрипта и собранного EXE. Все артефакты проекта теперь выпускаются под одним номером версии.
- Консоль и GUI: стартовая валидация карт патчей (`Assert-PatchMap`), отклоняющая некорректные KB-идентификаторы и несогласованные пороги UBR до начала детекции.
- Консоль: коды выхода процесса для автоматизации:
  - `0` = OK / защищена / не затронута;
  - `1` = ошибка валидации или детекции;
  - `2` = требуется установка исправления.
- Консоль и GUI: предупреждение при запуске без прав администратора, так как DISM и часть истории обновлений могут быть доступны не полностью.
- GUI: запрос `Win32_QuickFixEngineering` через CIM как дополнительный источник детекции KB.
- GUI: поддержка Windows Server 2012 и Windows Server 2012 R2; для этих сборок, а также для Windows Server 2016 и Windows 10 1607 / LTSB 2016 отключена UBR-детекция через флаг `UbrCheckDisabled`.
- GUI: фильтрация истории WUA по `ResultCode = 2`, чтобы учитывать только успешные установки.
- GUI: детерминированное освобождение формы после `ShowDialog()`.
- GUI: кнопка «Re-check» перезапускает скрипт с использованием текущего хоста PowerShell.
- GUI: DISM-детекция выполняется в фоновой задаче с таймаутом 30 секунд.
- GUI: запасной путь копирования в буфер через `Set-Clipboard`, если `[System.Windows.Forms.Clipboard]::SetText()` завершается ошибкой.
- `.gitattributes` для нормализации переводов строк в репозитории (LF для исходников и документации, CRLF для `.bat`/`.cmd`, binary для изображений и исполняемых файлов).
- README (EN и RU): секция «Проверено на живых системах» со сводной таблицей протестированных конфигураций (Server 2016/2019/2022, Windows 10 22H2), значением UBR на момент проверки, итоговым вердиктом и источником детекции, который его вынес.

### Изменено
- Шапки скриптов и GUI теперь указывают единую версию проекта `1.2.0`.
- Консольная детекция по-прежнему документируется как четыре источника: Registry UBR, `Get-HotFix`, WUA history и DISM.
- GUI-детекция документируется как пять источников после добавления `Win32_QuickFixEngineering`.
- Консоль и GUI: KB-идентификаторы нормализуются через `Trim().ToUpperInvariant()` перед валидацией.
- Консоль и GUI: сопоставление истории WUA использует границы слова, чтобы не совпадать с более длинными KB-номерами.
- Консоль и GUI: результаты `Get-HotFix` и `Win32_QuickFixEngineering` сокращаются до первого объекта; разбор дат защищён `try/catch`.
- Консоль и GUI: список пакетов DISM кешируется один раз за запуск вместо отдельного вызова `dism.exe` для каждого KB.
- Консоль и GUI: текущее значение UBR читается один раз и передаётся в `Test-KbInstalled`, чтобы не опрашивать реестр повторно.
- Консоль и GUI: определение ОС/ProductType использует один CIM-запрос и отказывается от некорректных значений ProductType вместо угадывания.
- Консоль и GUI: порядок вердикта изменён — сначала проверяется наличие исправления, прежде чем делать вывод об отсутствии проблемного обновления.
- Консоль: `-OpenLink` открывает Microsoft Update Catalog только когда исправление требуется и не установлено.
- Консоль: список поддерживаемых сборок сортируется в диагностике неизвестной сборки.
- GUI: UBR-детекция учитывает `UbrCheckDisabled` и показывает пониженную достоверность для сборок, где пороги UBR ненадёжны.
- GUI: кнопки ссылки на скачивание активны только когда система уязвима и требуются действия.
- GUI: правило цвета для `[!] WARNING` проверяется раньше общего правила `[!]`.
- GUI: кнопка Re-check определяет текущий хост PowerShell через `$PSVersionTable.PSEdition` и `$PSHOME`.
- GUI: `Start-Process` использует однострочный `ArgumentList` для действия Re-check.
- GUI: определение ОС и конвейер детекции обёрнуты в обработку ошибок, показывающую MessageBox вместо падения в консоли.
- Удалены все предупреждения PSScriptAnalyzer:
  - Пустые блоки `catch` теперь логируют через `Write-Verbose` вместо молчаливого проглатывания (правило `PSAvoidUsingEmptyCatchBlock`).
  - Использование `Write-Host` в консольном скрипте подавлено на уровне файла через `[Diagnostics.CodeAnalysis.SuppressMessageAttribute]`, обосновано интерактивным цветным выводом (правило `PSAvoidUsingWriteHost`).
- Устранены все предупреждения Remark-lint в обоих CHANGELOG:
  - Добавлены определения reference-ссылок для каждого заголовка версии.
  - Заголовки переведены в collapsed-форму (`[X][]`).
  - В конце файлов добавлен перевод строки.
- Исправления документации:
  - README: количество источников детекции в консоли исправлено на «four sources» (соответствует удалению `Get-WindowsPackage` в v1.0.4); количество источников в GUI документируется отдельно, так как v1.2.0 добавляет `Win32_QuickFixEngineering`.
  - README: таблица «Verified UBR values» обновлена — добавлены Server 2025, Windows 10 21H2/22H2, Windows 11 23H2/24H2/25H2/26H1 и отметка об отключении для Server 2016.
  - README: секция «Supported systems» переписана в виде трёх уровней (Supported / Legacy / Unknown).
  - README (EN и RU): исправлен перечень источников детекции в Шаге 3. В списке отсутствовал `via Registry UBR`, что противоречило и коду, и таблице «Verified UBR values» ниже.
  - README (EN и RU): уточнён FAQ про `Get-HotFix` — инструмент переключается на Registry UBR, если обновление установлено как LCU и не отображается в списке QFE.
  - README (EN и RU): примечание о непокрытости Windows Server 2012 / 2012 R2 в GUI уточнено: эти сборки обрабатываются, но UBR-детекция для них отключена из-за ненадёжных порогов.
- Code Scanning на GitHub теперь показывает 0 открытых алертов по всем четырём инструментам (PSScriptAnalyzer, Remark-lint и двум другим).

### Исправлено
- GUI: фатальная ошибка `OrderedDictionary.ContainsKey` в Windows PowerShell 5.1. Поиск legacy-сборок теперь использует `$LegacyBuilds.Keys -contains $build` вместо `$LegacyBuilds.ContainsKey($build)`.
- Консоль и GUI: ложный вердикт «не затронута», если исправление установлено, но проблемный KB не был обнаружен. Теперь исправление имеет приоритет в вердикте.
- Консоль и GUI: хвостовые пробелы или строчные `kb` в KB ID больше не приводят к тому, что корректные обновления считаются недействительными или отсутствующими.
- Консоль и GUI: история WUA больше не рискует совпасть с `KB5122878` внутри более длинного KB-номера, например `KB51228781`.
- Консоль: опечатка `$($.Exception.Message)` в catch-блоках `Get-CurrentUbr` исправлена на `$_.Exception.Message`.
- Консоль и GUI: пустые или некорректные результаты CIM/WMI больше не приводят молча к ProductType `0` и неверной карте патчей.
- GUI: кнопки Copy/Open больше не активны в состояниях protected, not affected, legacy или unknown.
- GUI: сбои доступа к буферу обмена больше не выбрасывают необработанные исключения.
- GUI: строки предупреждающего цвета теперь отображаются корректно.
- GUI: Re-check больше не зависит от недоступной `$IsCoreCLR` в Windows PowerShell 5.1.

## [1.1.1][] — 2026-10-15

### Исправлено
- `Get-OsProductType` теперь возвращает `$null` вместо `0` при ошибке. Ранее сбой CIM/WMI интерпретировался ниже по коду как «не Server → использовать клиентскую карту». На сборке 26100 (Server 2025 vs Win11 24H2) это могло дать вердикт по чужим KB. Теперь скрипты отказываются угадывать, если ProductType неизвестен.
- `Get-CurrentUbr` сузил фильтр исключений до конкретных типов (`ItemNotFoundException`, `UnauthorizedAccessException`, `SecurityException`). Неожиданные ошибки теперь выводятся как предупреждения, а не проглатываются молча generic-`catch`.
